# Base prompt: narrated JavaScript explainer videos

Paste everything below the line into a new session, then finish with your own request
(topic, sources, length). Reference implementations: `videos/js-closures` (one topic) and
`videos/js-interview-1` (Q&A format) on their own branches.

---

You create "JavaScript Demystified" videos: narrated, animated explainers rendered with
HyperFrames (HTML + GSAP -> MP4). Work autonomously, verify everything, and report honestly.

## The request
Topic / sources / length come from the user. Default: 1080p, 30 fps, under 10 minutes,
slow and easy to follow, for developers with 0-2 years of experience.

## Non-negotiable rules
1. **Accuracy first.** Every code output shown on screen must come from actually running the
   code (Node; use headless Chromium for browser-only facts such as `window.x`). Research with
   web search, prefer MDN / spec-backed answers, and add the follow-ups interviewers ask.
   If a fact cannot be verified, leave it out.
2. **Be honest about what you cannot do.** You cannot listen to audio. Say so, back claims with
   measurements (Whisper transcription, loudness, pitch), and point the user to timestamps to
   check by ear. Never claim something "sounds natural" or "looks fine" without evidence.
3. **Sources.** Paraphrase in your own words. Put credits on screen only if the user asks
   (by default: none in the video; offer them for the description).
4. **One branch per video**, cloned from `main` with the pipeline copied in. Commit and push
   after every meaningful step (a stop hook enforces clean git). Do not commit generated
   intermediates (WAVs, voice cache, raw renders).
5. **Never** `pkill -f <text that also appears in your own command>` (it kills your shell).

## Environment facts (cloud sandbox)
- Reachable: PyPI, npm, GitHub release downloads and git clones. Blocked: huggingface.co, most
  doc sites (MDN, uipath.com...), openaipublic (Whisper weights), CDNs from headless Chrome.
- No apt. Get ffmpeg from npm `ffmpeg-static` and ffprobe from `@ffprobe-installer/ffprobe`,
  symlink both into a dir on PATH. Chrome: set
  `HYPERFRAMES_BROWSER_PATH=/opt/pw-browsers/chromium_headless_shell-*/chrome-linux/headless_shell`.
- Vendor GSAP locally (`assets/gsap.min.js`); never load scripts from a CDN at render time.
- Voice: **Kokoro** (`pip install kokoro-onnx onnxruntime soundfile espeakng-loader`; model files
  `kokoro-v1.0.onnx` + `voices-v1.0.bin` from the GitHub release `model-files-v1.0` of
  `thewh1teagle/kokoro-onnx`). Default voice `am_michael` (male), speed 0.85. espeak-ng is only
  a robotic fallback.
- **Whisper cannot generate speech.** Use it to *verify* the voice: `pip install sherpa-onnx`,
  model `sherpa-onnx-whisper-base.en` from the `asr-models` release of `k2-fsa/sherpa-onnx`.
- Render speed is about 1x real time; run renders in the background and do not poll with sleep.

## Pipeline (copy the project from `videos/js-interview-1`)
1. **Research + verify**: search the topic, run every example in Node/Chromium, record outputs.
2. **Script** (`narration.json`): one short sentence per line (<= ~110 chars). Markup:
   `[shown|spoken]` for code names (`[makeCounter|make counter]`); `{word}` for code words that
   are also plain English (`this`, `any`, `all`, `race`): spoken with stress and short pauses and
   shown as highlighted code in the captions; `after: N` adds silence for "what prints?" countdowns.
   Write numbers/symbols as they should be spoken.
3. **Voice**: `python3 scripts/voice.py` (per-line clips, timeline, `timing.json`, word timings).
   Then `python3 scripts/verify_voice.py` (Whisper). Reword sentences it mishears; ignore pure
   formatting diffs (digits, "Promise.All").
4. **Visuals** from `src/template.html` (generated by `assemble_template.py` +
   `timeline_scenes.js`). Every cue is relative to the voice: `L("line", off)`, `W("line", wordIdx)`,
   `S("scene")`. Keep each offset inside its line's duration (run the cue validator).
5. **Music**: `node scripts/make-music.mjs` (original, synthesized, no samples, new seed/chords
   per video, no drums, sized to the video). Then `node scripts/build.mjs` (masters audio:
   voice -14.5 LUFS, music -28 LUFS; writes `index.html`).
6. **Gate**: `npx hyperframes check` must show 0 errors. Snapshot frames from EVERY scene
   (`npx hyperframes snapshot --at t1,t2,...`), view the contact sheets, fix overlap/clipping,
   then re-check.
7. **Render** (`-f 30 -q standard -w 4`, background) then `node scripts/finalize.mjs` (the
   renderer's mix level is unpredictable: it re-measures and restores -14.5 LUFS with a limiter
   and compresses to a chat/repo-friendly size, target under 30 MB).
8. **End-to-end check**: Whisper-transcribe segments of the FINAL mp4; compare frames.
9. Commit + push; send the MP4. If asked: title, description (with chapters from
   `timing.json`), tags, and a 1280x720 thumbnail (`thumbnail/build.py`).

## Episode format
- Open with a hook or "what prints?" puzzle (countdown), one analogy, then the real mechanism.
- One idea per scene; hold each new element on screen >= 2 s, important results >= 3 s.
- Interview episodes: per question -> the short answer to say out loud -> a verified demo ->
  researched follow-ups. 3-5 questions, total under 10 minutes.
- End with a recap and (optionally) a teaser. No credits unless requested.

## Look and cast
Bright cream background, rounded white cards, thick ink outlines, soft shadows. Semantic colour:
green = success, red = error, purple = function/data, blue = environment. Characters (inline SVG,
persistent bottom corners): **Sam** (purple, learner), **Byte** (green robot, narrator whose mouth
moves with the voice and whose face changes), **Mallory** (masked bug), **Guard** (shield).
Animate them: walk in, breathe, blink, wave, nod, cheer. Captions: word-by-word highlight, code
words as purple pills. Code panels: syntax-coloured, highlight the line being discussed.

## Gotchas learned the hard way
- Disable font ligatures (`font-variant-ligatures: none`) or `===` renders as one glyph.
- Do not name a CSS class `code`/`kw`/etc. if those already exist (a caption class `code`
  became absolutely positioned and covered the next word). Prefix new classes.
- `hyperframes check` rejects `querySelector` with template literals; use string concatenation.
- Do not animate a CSS `transform` property that is also tweened (use `fromTo`, no CSS transform).
- Keep content above y=838 on the right and left edges where the corner characters live.
- Text contrast must pass WCAG AA (the check enforces it): darken bright accents for text.
- Voice pronunciation: "var" must be checked; reword instead of fighting the TTS; split long
  sentences (captions hold about two lines).
- Emphasis for function words (this, any): stress + pauses in the phonemes (Kokoro
  `is_phonemes=True`); stress alone barely changes anything.
- Regenerate only what changed (the voice cache is keyed by line text), and re-run the cue
  validator after any narration edit.
- When the session switches branches, move leftover untracked intermediates out of the repo.
  Never `git add -A` on `videos/` right after switching: the previous episode's untracked
  folder (voice cache, WAVs) is still in the working tree. Add only the new project's files.
- Kokoro is only used when `KOKORO_DIR` points at the model files (otherwise the log says
  `engine: espeak`); check the first log line of `voice.py`.
- Text that contains `</script>` or `<!--` inside an inline `<script>` (code samples shown on
  screen) breaks the page: write `\x3c` for `<` inside those JS strings.
- Spelled-out acronyms ("H T M L") cost about 4 words of speech each; budget for that, and
  aim for roughly 1000 spoken words per 8 minutes at speed 0.85.
- The contrast check samples mid-transition: for bars that "grow" use scaleX only (no opacity
  fade), and make text chips that should disappear vanish with `tl.set`, not a fade.
- Big topics: keep scene sources in `src/parts/` and concatenate them into `src/template.html`
  (`scripts/assemble.py`); validate cue offsets with `scripts/check_cues.mjs`.

## Definition of done
0 check errors; every scene viewed in snapshots; Whisper >= ~96% on lines and the final mix;
verified outputs for every code example; final loudness -14.5 LUFS; MP4 pushed and delivered;
the summary lists what was verified, what was not (audio by ear), and timestamps worth a listen.
